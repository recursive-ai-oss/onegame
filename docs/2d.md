# Drawing in 2D

A 2D game draws from **view code**: an entity that implements `IView2D` gets a `Draw(Draw2D d)` call every frame, and what it draws appears under the UI. No render stage of your own. View code reads state and never writes it (assigning a synced property in `Draw` is a compile error).

```csharp
using System.Numerics;
using OneGame.Core;
using OneGame.Host;
using OneGame.UI;

[Entity]
public partial class Ship : Entity, IView2D
{
    [Synced] public partial Fixed X { get; private set; }
    [Synced] public partial Fixed Y { get; private set; }

    [View]
    public void Draw(Draw2D d) =>
        d.Sprite("art/ship.png", new Vector2(X.ToSingle(), Y.ToSingle()), scale: 2, tint: Color.White);
}
```

The path is loaded once through the game's asset service and cached, so calling it every frame is cheap, and an edited file shows up while the game runs ([assets.md](assets.md)). World units are pixels at zoom 1: +X right, +Y down, rotation in radians, clockwise.

## Sprites, shapes, text

Sprites, shapes and text take an optional `z` (higher draws later); ties keep call order, so a sprite drawn after a text covers it and a text drawn after a sprite is over it. Sprites take `rotation`, `scale`, `tint`, `origin` (a fraction of the sprite, default its centre) and `flip`.

```csharp
[View]
public void Draw(Draw2D d)
{
    d.FillRect(new Rect(-400, 16, 800, 24), Color.Rgb(0x35506b));
    d.StrokeRect(new Rect(-400, 16, 800, 24), Color.Rgb(0x8fb8de), 2);
    d.Line(new Vector2(-120, 16), new Vector2(-120, -40), Color.Rgb(0xd0d0d0), 2);
    d.FillCircle(new Vector2(60, -8), 8, Color.Rgb(0xf2c14e));
    d.StrokeCircle(new Vector2(60, -8), 12, Color.Rgb(0xf2c14e), 1.5f);

    d.Text("hero", new Vector2(0, -24), 12, Color.White, new Vector2(0.5f, 1)); // in the world, anchored bottom-centre
    d.ScreenText("walk with Go", new Vector2(8, 8), 14, Color.Rgb(0xdddddd));     // in window pixels, for a HUD
}
```

Text is one line, unrotated, in the game's fonts. For anything that wraps or reacts to clicks, use the UI ([ui-guide.md](ui-guide.md)). A text size that is new every frame (a label that pulses) costs a little more than one that repeats; text that is drawn at sizes you know in advance can be prepared once with `d.WarmUpText("0123456789", size)`, so the first frame that shows it does not stop to rasterize the glyphs. Sprites can also come from a texture you already hold, a pixel rectangle of it, or a hand-built `Sprite` (`d.Sprite(in Sprite)`).

## Sprite sheets and clips

A sheet cuts one picture into equal frames; clips name runs of frames and play against view time (`d.Time`), so animation is smooth in play, identical in captures and replays, and frozen while the sim is paused.

```csharp
private SpriteSheet? _sheet;

[View]
public void Draw(Draw2D d)
{
    if (_sheet is null)
    {
        _sheet = SpriteSheet.Grid(d.Texture("art/hero.png", TextureFilter.Nearest), 16, 16);
        _sheet.AddClip("walk", 0, 4, 8);   // first frame, count, frames per second
        _sheet.AddClip("idle", 4, 2, 2);
    }

    var at = new Vector2(X.ToSingle(), 0);
    d.Sprite(_sheet, Speed == Fixed.Zero ? "idle" : "walk", at, scale: 2,
        flip: Speed < Fixed.Zero ? SpriteFlip.Horizontal : SpriteFlip.None, z: 1);
}
```

`d.Sprite(sheet, frame, ...)` draws a single frame by number. `SpriteSheet.Frames(texture, rects)` takes explicit rectangles instead of a grid. An unknown clip name throws `UnknownClipException`. To play a clip from a moment, pass `clipTime: d.Time - startedAt`.

## The camera

`d.Camera` is a rig that every `Draw2D` call shares:

```csharp
d.Camera.Zoom = 2;                                 // physical pixels per world unit
d.Camera.Bounds = new Rect(-400, -300, 800, 600);  // keeps the view inside this world rectangle
d.Camera.Smoothing = 0.15f;                        // follow time constant in seconds; 0 = exact
d.Follow(new Vector2(X.ToSingle(), 0));            // centre on a point (smoothed)
var world = d.ScreenToWorld(new Vector2(320, 200)); // a pixel to a world point
var pixel = d.WorldToScreen(new Vector2(60, -8));   // and back
```

`d.Camera.Snap(position)` jumps without smoothing; `Rotation` turns the view. Smoothing depends on how many frames were drawn, so keep it at 0 where captures must repeat exactly.

## Layers: a HUD over a zoomed world, a second camera

Everything is drawn in order of **layer** (in the order the layers were made), then `z`, then call order. A frame starts on the scene's default layer, which follows `d.Camera`. Two more kinds of layer cover the usual needs:

```csharp
[View]
public void Draw(Draw2D d)
{
    d.Camera.Zoom = 3;                       // the world, zoomed, on the default layer
    d.Follow(new Vector2(X.ToSingle(), Y.ToSingle()));
    d.Sprite("art/ship.png", new Vector2(X.ToSingle(), Y.ToSingle()));

    d.Layer = d.ScreenLayer;                 // pixels, no camera: a HUD keeps its place and size at any zoom
    d.FillRect(new Rect(8, 8, 150, 34), Color.Rgb(0x000000) with { A = 170 });
    d.Text("fuel 82", new Vector2(14, 14), 16);

    var mini = d.GetLayer("minimap");        // a second view of the world in a corner
    mini.Camera = Camera2D.Default with { Zoom = 0.1f };
    mini.Viewport = new Rect(356, 12, 112, 80);
    d.Layer = mini;
    d.FillRect(new Rect(-4000, -4000, 8000, 8000), Color.Rgb(0x0c1118), 0, -1);
    d.FillCircle(new Vector2(X.ToSingle(), Y.ToSingle()), 40, Color.Rgb(0xf2c14e));
}
```

- `d.Layer` is the layer new sprites, shapes and text go on; it is reset to the default layer at the start of every frame.
- `d.ScreenLayer` is a layer made on first use, in front of the layers that exist then, whose coordinates are framebuffer pixels (origin top-left) whatever the camera does. `ScreenText` draws at a screen pixel on any layer.
- `d.GetLayer(name)` finds or makes a layer; layers stay between frames and draw in the order they were made, so ask for them in the same order every frame. A layer's `Camera` (a `Camera2D`) replaces `d.Camera` for that layer; `Viewport` confines it to a rectangle of the screen (its camera is centred on the rectangle, and nothing outside it is drawn, text included); `ScreenSpace` makes it pixel-addressed; `Parallax` and `Visible` work as before.
- `d.WorldToScreen(layer, point)` and `d.ScreenToWorld(layer, pixel)` convert through a layer's own camera, for picking in a minimap.
- A scene with a single camera needs none of this: nothing changes until a layer is given a camera.

## Render textures and post effects

Two more things sit on layers. Both cost nothing until you use them: a frame without a render texture or a chain has no extra pass and draws exactly as before.

**Render textures** are images you draw into and then show as sprites: a minimap, a reflection, a complex layer drawn once and reused. A layer aimed at one draws there instead of on the frame, in the texture's own pixels:

```csharp
private RenderTexture2D? _badge;

[View]
public void Draw(Draw2D d)
{
    _badge = d.RenderTexture("badge", 96, 96);                    // made once, kept by name, any size you like
    var fill = d.RenderLayer("badge", _badge, new Color(14, 30, 24));   // a layer that draws into it (pixel coordinates), cleared to this colour
    var world = d.GetLayer("world");                              // made after it, so it draws after it

    d.Layer = fill;
    d.FillCircle(new Vector2(30, 36), 9, Color.Rgb(0xf2c14e));
    d.Text("MAP", new Vector2(48, 80), 14, Color.White, new Vector2(0.5f, 0.5f));

    d.Layer = world;
    d.Sprite(_badge.Texture, new Vector2(-150, 0));                   // the texture is an ordinary sprite texture
    d.Sprite(_badge.Texture, new Vector2(0, 0), rotation: 0.4f, scale: 1.8f);
}
```

- The layer that fills a texture has to come before the layer that shows it (layers draw in the order they were made); a layer earlier in the order shows what the previous frame left.
- The texture is cleared to the layer's `TargetClear` (transparent by default) the first time a layer draws into it in a frame. A layer with nothing to draw leaves the texture as it was, so to cache a complex layer, draw into it only on the frames its contents change. `keep: true` never clears, so drawing accumulates.
- A texture has the renderer's target format. Drawing a texture into itself throws `InvalidOperationException`; for feedback (trails) alternate two textures.
- Free a texture you no longer need with `Dispose` (`d.RenderTexture` with another size for the same name does it for you).

**Post effects** are chains of full-screen passes run over a finished image: the whole frame (`d.Post`, everything `Draw2D` drew, not the UI above it) or one layer (`layer.Post`; the layers above it stay sharp, which is how a HUD stays crisp under a glowing world).

```csharp
_bloom ??= d.CreatePostChain().AddBloom(threshold: 0.55f, intensity: 1.4f, blurPasses: 4);
d.GetLayer("world").Post = _bloom;       // glow the world only; the HUD layer above it is not touched
// or: d.Post = _bloom;                  // the whole frame
```

- Built-in effects: `AddBloom(threshold, intensity, radius, softness, blurPasses, downscale)` (bright parts, blurred at half size, added back), `AddBlur(radius)`, `AddGrade(exposure, contrast, saturation, vignette, tint, tintAmount)`.
- Your own pass: write a pixel shader (HLSL in your project, compiled by the shader build package), make it a material with `d.Renderer.CreateMaterial(...)` and `chain.AddMaterial(material)`. It reads the image so far as `Tex`/`Samp` (set 1), parameters as `P[0..7]` (set 2, `material.SetParameter`) and the size of the image being drawn as `Viewport` (set 0), and returns premultiplied colour. `examples/glow/Shaders/Scan.hlsl` is a complete one.
- A chain is made once and kept (it owns GPU objects); set `d.Post` or `layer.Post` to null, or to a chain with no effects, to stop. A chain used on two images in one frame needs them to be the same size.
- Cost: bloom adds about nine passes at half size, a blur two, a grade or your own pass one, each full-screen. `onegame capture` and `draw_view` show the result like anything else.

`examples/glow` shows a render texture drawn as sprites, bloom on the frame, a pass of the game's own, and bloom on one layer with a HUD above it; its scenario captures are the references.

## Dropping down

When the happy path is not enough, the layers underneath are open. `d.Scene` is the frame's `Scene2D`, `d.Layer` the layer new sprites go on, and `d.Scene.AddLayer(name, parallax)` makes a scrolling background layer. `Scene2D.Mark` puts a marker in the draw order and `Renderer2D.DrawScene` hands it back to an `ISceneMarkerSink`, which is how `Draw2D` interleaves text with sprites. `d.Renderer` is the `Renderer2D`, for textures made from pixels (`CreateTexture`), tile maps, custom pixel-shader materials, `BeginTarget`/`EndTarget` and post-processing. Draw them from a render stage's `DrawOverUi`, alongside the entities' `Draw` calls. The engine-side contracts are in `docs/interfaces/render2d.md`.

## Look at it

```
onegame capture --out shots/main.png --size 720p --after 30 --json
```

Captures and the scenario `capture` expectation include everything drawn here. The control operation `draw_view` reports the last frame's sprite and text counts, the tick, and the camera, and converts between screens and worlds: `draw_view` with `{"screen":[160,100]}` returns the world point under that pixel, `{"world":[60,-8]}` the pixel of a world point. `tests/Draw2DGame` is a worked example: a walking hero with a clip, a follow camera, shapes and text, scenario captures of a zoomed world with a zoom-1 HUD and a corner camera, and of text and sprites covering one another.
